# 새벽 4시: 괴담 탈출! (4 A.M. Urban Legend Escape)

HTML5 `<canvas>` + CSS + 순수 JavaScript로 만든 2D 탑다운 미로 추격·탈출 게임.
열쇠를 모두 모아 출구를 열고, 괴담 신부 **WKB**에게 잡히기 전에 탈출하세요.

## 실행 방법

- 가장 쉬운 방법: `index.html`을 더블클릭해서 브라우저로 열기 (서버 필요 없음)
- 로컬 서버로 열기: `npx http-server my-game2 -p 5174` → http://localhost:5174

## 조작법

| 동작 | 키보드 | 모바일 |
|---|---|---|
| 이동 | 방향키 / WASD (꾹 누르면 연속 이동) | 화면 아래 D-Pad, 또는 보드 위 스와이프 |
| 일시정지 | P 또는 Esc | HUD의 ⏸ 버튼 |
| 재시작 | R | 일시정지 → 다시 하기 |

## 화면

- **레트로 픽셀아트:** 한 칸을 16×16 도트로 그린 뒤 크게 늘려서(`image-rendering: pixelated`) 보여 준다. 글꼴은 한글 도트 글꼴 [갈무리](https://github.com/quiple/galmuri)(SIL OFL, jsDelivr에서 불러옴).
- **창에 꽉 차게:** 맵이 들어가는 가장 큰 칸 크기를 고르고, 남는 가장자리는 같은 벽돌로 채운다.
- **웹은 가로형, 모바일은 세로형:** 맵은 가로로 길게(21×13) 만들어 두고, 게임판 자리가 세로로 더 길면 맵을 대각선으로 뒤집어(행↔열) 세로형(13×21)으로 보여 준다. 길 구조는 그대로라 난이도도 같다. 게임 도중 휴대폰을 돌리거나 창 크기를 바꿔도 그 자리에서 뒤집힌다.

## 등장 요소

| 요소 | 모양 | 효과 |
|---|---|---|
| 나 | 파란 후드 아이 | 4방향 타일 이동 |
| WKB | 흰 베일 + 빨간 가시관 + 근육 팔 | BFS로 벽을 돌아서 추격. 닿으면 게임 오버. 흥분하면 빨간 테두리 |
| 열쇠 | 노란 열쇠 | 다 모으면 출구 열림 |
| 출구 | 회색 문 + 자물쇠(잠김) / 깜빡이는 초록 문(열림) | 열린 출구에 닿으면 클리어 |
| 코기블린 | 주황 코기 얼굴 | 복도를 순찰. 닿으면 -5초 |
| 해피 | 분홍 정육면체 | 지나갈 수 없는 이동 장애물. 가끔 `HECK!` → WKB 2.5초간 빨라짐 |

## 파일 구성

```text
my-game2/
├── index.html      # 화면 구조 (시작 메뉴, HUD, 캔버스, 모달, D-Pad)
├── styles.css      # 디자인, 챕터별 색, 반응형/모바일
├── js/
│   ├── stages.js   # 스테이지 데이터 20개 + 맵 해석(parseStage) + 맵 검사(validateStage) + 가로/세로 뒤집기(transposeMap)
│   ├── render.js   # 픽셀아트 그리기 (도트 캐릭터 SPRITES, 벽돌/바닥 타일, 어둠 디더링)
│   ├── input.js    # 키보드 / D-Pad / 스와이프 입력
│   └── game.js     # 공통 게임 루프, 상태, 승패, 저장, 메뉴
└── README.md
```

## 새 스테이지 추가하는 법

`js/stages.js`의 `STAGES` 배열에 객체 하나만 추가하면 됩니다. 게임 코드는 건드릴 필요가 없습니다.
맵은 **가로로 긴 모양**으로 그려 주세요 (세로 화면에서는 게임이 알아서 뒤집습니다).

```js
{
  id: 21, chapter: 4, name: '보너스 스테이지',
  map: [
    '#########',
    '#P..K..E#',
    '#.#####.#',
    '#...W...#',
    '#########'
  ],
  timeLimit: 60,      // 제한 시간(초)
  enemyMoveMs: 500,   // WKB 이동 간격 (작을수록 빠름)
  keyCount: 1,        // 맵의 K 개수와 같아야 함
  corgiMoveMs: 400,   // (선택) 맵에 C가 있을 때
  happy: { moveMs: 800, shoutEveryMs: 8000, pauseMs: 0 }, // (선택) 맵에 H가 있을 때
  gimmick: null       // 또는 { darkness: true, rage: true }
}
```

맵 기호: `#` 벽, `.` 빈칸, `P` 플레이어, `W` WKB, `K` 열쇠, `E` 출구, `C` 코기블린, `H` 해피

페이지를 열면 `validateStage`가 모든 맵을 자동 검사하고, 문제가 있으면 브라우저 콘솔(F12)에 빨간 오류로 알려줍니다.
검사 항목: 줄 길이 통일, 모르는 기호, P/E/W 개수, 열쇠 수 일치, 열쇠·출구·적에게 갈 수 있는 길,
WKB가 유일한 통로를 막고 서 있지 않은지.

## 방어 로직 (PRD 7장)

| 항목 | 처리 방법 |
|---|---|
| 스폰 중첩 | 맵 글자 하나가 한 칸이라 겹칠 수 없음 |
| 맵 유효성 | `validateStage`로 시작 시 전체 검사 |
| 동시 판정 | 플레이어 이동 직후 WKB 충돌 → 코기 → 열쇠 → 출구 순서로 한 번만 판정, 승부 나면 그 프레임 종료 |
| 타이머 중복 | `setInterval`/`setTimeout`을 쓰지 않음. `requestAnimationFrame` 루프는 페이지당 1번만 시작 |
| 입력 연타 | 한 이동 틱에 방향 하나만 꺼내 씀 → 연타해도 한 칸씩, 벽 통과 불가 |
| 상태 초기화 | `loadStage`가 state를 새 객체로 교체 + 입력/모달 초기화 |
| 없는 스테이지 | `loadStage`가 못 찾으면 엔딩 화면 |
| 종료 후 정지 | `status !== 'playing'`이면 `update`가 바로 끝남 (적·타이머 멈춤) |
| 저장 오염 | JSON 깨짐·범위 밖 값이면 1스테이지로 복구, 저장 실패해도 계속 플레이 |
| 탭 전환 | 다른 탭으로 가면 자동 일시정지, 프레임 시간(dt) 최대 100ms로 제한 |

## 테스트한 것

- 20개 맵 자동 검사 통과 (가로형 17×11 ~ 21×13)
- 자동 플레이 봇: WKB를 멈춘 상태에서 20개 스테이지 모두 클리어 → 엔딩까지 연속 진행, 진행도 저장 확인
- 세로형(뒤집힌 맵)에서도 WKB 정지 시 20개 모두 클리어. WKB가 움직이는 조건에서 단순 봇(목표로 직진만 함)은 20개 중 16개 클리어
- 게임 도중 화면 방향 전환: 두 번 뒤집으면 원래 상태와 완전히 같음, 세로→가로 창 전환 시 자동으로 뒤집힘
- 코기 물림(-5초), 해피 길막·HECK 가속, 분노 기믹, 일시정지 중 시간 정지, 50회 연속 재시작, 손상된 저장 데이터 6종, 저장 거부
- 모바일(375×812): 세로형 맵이 HUD와 D-Pad 사이를 꽉 채움, 가로 스크롤 없음, D-Pad 동작
- 웹(1361×1266): 가로형 맵이 창 전체를 채우고, 남는 위아래는 벽돌로 채움
